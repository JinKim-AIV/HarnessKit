# 충돌 판정 기준

스킬·플러그인·출력 스타일·훅이 **함께 켜졌을 때 기능적으로 부딪히는지** 판정하는 기준이다. `hkcheck.py`가 확정한 항목(catalog, rule)은 그대로 보고하고, `review` 항목만 이 기준으로 판정한다.

## 1. 충돌 유형

| 유형 | 뜻 | 판정 질문 | 대표 예 |
|---|---|---|---|
| **trigger** 트리거 겹침 | 같은 요청에 둘 이상이 반응한다 | 사용자가 한 문장으로 요청했을 때 두 스킬 모두 "이건 내 일"이라고 볼 만한가? | 같은 이름의 스킬 두 벌, "다른 브라우저 도구보다 나를 우선하라"는 설명문 |
| **contradiction** 지시 모순 | 같은 상황에 반대로 지시한다 | 두 지시를 동시에 지키는 응답을 만들 수 있는가? 만들 수 없으면 모순이다 | "답하기 전에 스킬 사용을 먼저 알려라" vs "첫 문장은 결론" |
| **slot** 자리 경쟁 | 하나만 차지할 수 있는 자리를 다툰다 | 출력 스타일, 세션 시작 지침, 작업 절차 담당, 하네스 생성기 중 같은 자리인가? | 개발 절차 프레임워크 + 하네스 오케스트레이터 |
| **role** 역할 중복 | 같은 일을 하는 도구가 둘이다 | 하나를 끄면 잃는 기능이 있는가? 없으면 중복이다 | 메모리 도구 두 개, HWP 도구 두 개 |
| **side-effect** 부작용 경쟁 | 같은 설정·파일·네트워크 경로를 바꾼다 | 둘이 같은 설정 키, 같은 파일, 같은 API 경로를 고치는가? | 프록시 두 개, 같은 settings 키를 고치는 명령 |

## 2. review 항목 판정 절차

`hkcheck.py`의 `review` 항목은 "같은 의도를 주장한다"는 신호일 뿐이다. 다음 순서로 판정한다.

1. `evidence`에 있는 두 파일을 읽는다. 설명문(description)만이 아니라 본문의 지시도 읽는다. 세션 시작 훅이 주입하는 파일이 있으면 그것도 읽는다.
2. 두 스킬이 실제로 같은 요청에서 불릴지 판단한다. 대상(코드 vs 문서), 시점(작업 전 vs 완료 전), 산출물(리뷰 개요 vs 리뷰 의견)이 다르면 **충돌 아님**으로 닫는다.
3. 같은 요청에서 불린다면 지시가 서로 모순되는지 본다. 동시에 지킬 수 있으면 **역할 중복**, 지킬 수 없으면 **지시 모순**이다.
4. 근거 문장을 원문 그대로 짧게 인용한다. 인용할 문장이 없으면 판정을 **불확실**로 남기고 추측으로 채우지 않는다.

판정 결과는 `충돌 / 역할 중복 / 충돌 아님 / 불확실` 중 하나로 적는다.

## 3. 심각도

- **high**: 결과가 매번 달라지거나 지시를 지킬 수 없다. trigger, contradiction, 배타적 slot(output-style, process, harness-builder).
- **medium**: 비용이나 상태가 갈라진다. role, 비배타적 slot, 정책상 제외 도구.
- **low / info**: 상시 비용 경고, 외부 전송 알림.

## 4. 해결안

사용자에게 다음 세 가지 중에서 고르게 한다. 고르기 전에는 아무것도 바꾸지 않는다.

1. **하나만 남기기**: 프로젝트에 맞는 쪽을 남기고 나머지를 끈다.
2. **끄기 범위 줄이기**: 이 프로젝트에서만 끈다.
3. **둘 다 두고 우선순위 한 줄 추가**: 프로젝트 `CLAUDE.md` 또는 `AGENTS.md`에 어느 지시가 이기는지 한 줄 적는다. 예: `답변 첫 문장은 결론. 스킬 사용 안내는 결론 뒤에 짧게.`

### 끄는 방법

| 대상 | Claude Code | Codex |
|---|---|---|
| 플러그인 | `claude plugin disable <name>@<marketplace> --scope local` (이 프로젝트만), 또는 `/plugin` | 해당 없음 |
| 사용자·프로젝트 스킬 | `.claude/settings.local.json`의 `skillOverrides`에 `"<skill>": "off"` 또는 `"name-only"` | 스킬 폴더를 `~/.codex/skills-disabled/`로 옮긴다 |
| 출력 스타일 | `/config` → Output style | 해당 없음 |
| MCP 서버 | `claude mcp remove <name> -s local` 또는 `/mcp` | `~/.codex/config.toml`의 `[mcp_servers.<name>]` 블록 주석 처리 |

설정 파일을 고치기 전에는 원본을 같은 폴더에 `.bak-YYYYMMDD-HHMM`으로 복사한다. 바꾼 내용과 이유는 `harnesskit.lock`의 `decisions`에 남긴다.

## 5. 보고 형식

```
충돌 체크 결과 (설치됨 N개, 후보 M개)

| # | 심각도 | 유형 | 대상 | 근거 (원문 인용) | 해결안 |
|---|---|---|---|---|---|

검토 판정: review 항목 K건 → 충돌 a건 / 역할 중복 b건 / 충돌 아님 c건 / 불확실 d건
상시 비용 상위: <항목> 약 N토큰/세션 ...
```

- 원문에서 확인한 내용과 추정을 구분해 적는다. 토큰 수는 추정치라고 밝힌다.
- 내장 기능으로 더 잘 볼 수 있는 것은 안내만 한다. 사용 기록 기반 점검은 `/skill-doctor`, 지시문 감사는 `/doctor prompt-audit`, 플러그인별 토큰 예측은 `claude plugin details <name>`을 쓴다.
