# 토큰 운영: 적게 쓰는 설계와 실행 운영 블록

`mode-build.md` 2-4(설계안)에서 1절을, 5-8(오케스트레이터 작성)에서 2~5절을 읽는다. 2~4절의 블록은 사용자 언어로 옮겨 오케스트레이터에 넣는다.

**왜 넣는가.** 토큰은 대체로 "도구 호출 수 × 그때의 대화 크기"로 쌓인다. 대화가 길면 호출할 때마다 대화 전체를 다시 읽고, 에이전트가 손으로 재거나 반복마다 전체를 다시 보면 호출 수가 는다. 설계로 호출 수를, 운영으로 대화 크기를 줄인다.

## 1. 승인 전 안티패턴 점검

설계안을 보여 주기 전에 점검한다. 걸린 것은 설계를 고친 뒤 보여 준다. 그대로 둘 이유가 있으면 설계안 `참고`에 한 줄 적는다.

| 안티패턴 | 고치는 곳 |
|---|---|
| 큰 파일을 통째로 읽는 에이전트 | 단위 소스·지도 (5-1) |
| 손으로 재는 리뷰어 | 측정 스크립트 → 판정만 (5-1) |
| 반복마다 전체 재검사 | 바뀐 것만 재검사 (5-1) |
| 한 세션에 여러 실행 | 실행 하나 = 세션 하나 (2절) |
| 상한 없는 에이전트 | 도구 호출 상한 (5-1, 2절) |
| 장부 없음 | `hktokens.py` (2·4절) |

「한눈에」의 토큰 위험은 "반복 횟수 × 반복마다 읽는 분량"으로 적는다. 예: "검사↔수정 최대 2회 × 고칠 파일만(약 10KB)".

## 2. 운영 규칙 블록 — 오케스트레이터 「공통 규칙」 아래

````markdown
### 운영 규칙 (토큰·세션)

토큰은 대체로 "도구 호출 수 × 그때의 대화 크기"로 쌓인다. 아래 규칙은 둘을 함께 줄인다.

- **토큰 장부.** `HK`는 `~/.claude/skills/harnesskit/scripts`(Codex는 `~/.codex/skills/harnesskit/scripts`), `<RUN>`은 이번 실행 시작 시각(`run-YYYYMMDD-HHMM`)이다. 단계를 시작할 때 그 단계의 첫 명령과 한 번의 Bash 호출로 묶어 실행한다.
  `python3 "$HK/hktokens.py" mark "<RUN> <단계>" [--cap <에이전트>=<상한> ...]`
  에이전트를 부르지 않는 단계는 `--cap` 없이 쓴다. Codex는 `--runtime codex`를 붙인다(토큰은 '측정 안 됨', 구간 시간만 남는다). 스크립트가 없거나 실패하면 장부 없이 진행하고 보고서에 '측정 안 됨'으로 적는다. 숫자를 짐작해 채우지 않는다.
- **mark가 출력한 줄은 그대로 따른다.** 세션 폴더 경고는 사용자에게 전한다. 대화 크기·실행 누계 경고는 아래 「실행 도중 제안」을 한다.
- **도구 호출 상한.** 에이전트를 부르는 프롬프트에 "도구 호출 상한 N회. 닿으면 멈추고 끝낸 것·남은 것을 보고한다"를 쓰고, 같은 값을 그 단계 mark의 `--cap`에 적는다. 메인은 남은 일만 다시 맡긴다.

| 에이전트 | 일 | 상한 (추정값) |
|---|---|---|
| <이름> | 빌드 · 수정 | 40 · 15 |
| <이름> | 첫 검사 · 재검사 | 30 · 15 |

  상한은 추정값이다. 보고 단계 장부의 「에이전트별 도구 호출」과 비교해 회고(evolve)에서 고친다.
- **중간 보고는 한두 줄**(끝낸 것, 다음 할 것). 표·로그·캡처는 대화에 옮기지 않고 파일 경로만 적는다. 이어서 돌릴 스크립트는 한 번의 호출로 묶는다. 에이전트 보고서는 첫 줄(판정)부터 읽고 불합격일 때만 표를 읽는다.
- **단계가 끝나면 다음 단계가 읽을 것을 모두 `_workspace/` 파일에 둔다.** 대화에만 있는 결정은 새 세션에서 사라진다. 인계 파일 크기는 다음 mark와 묶어 `python3 "$HK/hktokens.py" size <인계 파일 glob>...`로 본다. 종료 코드 1이면 넘은 파일을 나눈다.
- **실행 도중 제안.** mark가 기준을 넘었다고 하거나(기준은 추정값), 같은 단계를 2회 넘게 반복했거나, 사용자가 방향을 크게 바꾸면: 지금 단계까지 파일로 남기고 `_workspace/00_next_prompt.md`를 쓴 뒤 "대화가 길어졌습니다(대화 크기 약 N). 새 세션에서 이어 할까요?"라고 한 줄로 묻는다. 한 실행에 한 번만 묻고, 계속하라고 하면 그 실행이 끝날 때까지 다시 묻지 않는다.
- **실행 하나 = 세션 하나.** 이 대화에서 이미 보고 단계를 마쳤는데 새 요청이 오면 바로 시작하지 않는다.
  1. `_workspace/00_request.md` 끝에 요청 원문을 그대로 덧붙인다(「추가 요청 (N차)」).
  2. `_workspace/00_next_prompt.md`를 쓴다.
  3. "프로젝트 폴더(<경로>)에서 새 세션을 열고 `_workspace/00_next_prompt.md 대로 해줘`라고 하세요"라고 안내한다. 사용자가 여기서 계속하라고 하면 따른다.
- **`00_next_prompt.md`로 시작한 세션**은 0단계에서 그 파일부터 읽고 첫 줄에 `사용함: <RUN>`을 붙인다. 이 줄이 있는 파일은 다시 인계로 쓰지 않는다.
````

## 3. `00_next_prompt.md` 틀

다음 세션이 대화 없이 이 파일만으로 시작할 수 있어야 한다. 인계 파일이므로 짧게 쓴다(보통 1~3KB, 20KB 이하).

```markdown
<할 일 한 줄> (새 실행 | 이어 하기 — 이전 <RUN>은 <어디까지>). 세션은 <프로젝트 폴더>에서 연다.

먼저 읽을 것: <파일과 절 이름, 3개 안쪽>
실행 구분: <0단계 실행 구분의 행> · 반복 횟수 <0부터 | N회째부터>

할 일:
1. <단계> — <무엇을, 어느 파일까지>

이미 정한 것 (다시 묻지 않는다):
- <결정> — 근거: <사용자 말 원문 | 파일:줄>

주의:
- <이전 실행에서 겪은 함정, 하지 말 것>
```

## 4. 보고 단계 블록

```markdown
- `python3 "$HK/hktokens.py" report` → `_workspace/tokens/ledger.md`. 화면에 나온 요약 몇 줄만 읽는다.
- 보고서 「토큰」 절: 이번 실행 합계(메인 · 서브에이전트), 큰 구간, 상한을 넘었거나 상한이 없던 에이전트, 경고. 숫자는 장부 값만 쓴다. Codex는 '측정 안 됨'.
- 이전 실행과 비교하려면 작업 범위가 같은지 먼저 적는다. 범위가 다르면 "몇 % 줄었다"로 쓰지 않는다.
```

## 5. 끄기

설계안 「한눈에」의 '토큰 장부'를 사용자가 끄면 장부(mark·report·size)와 세션 제안(실행 도중 제안, 실행 하나 = 세션 하나, `00_next_prompt.md`)을 넣지 않는다. 도구 호출 상한과 중간 보고는 설계 원칙이라 남긴다. lock에는 `hklock.py write --data`의 `harness.token_ops`를 `"off"`로 적어 상태 점검이 다시 권하지 않게 한다.
