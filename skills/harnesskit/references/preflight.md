# 오케스트레이터 0단계 템플릿

생성하는 오케스트레이터 스킬의 0단계(기존 작업 맥락 확인) 앞에 아래 두 블록을 넣는다. 사용자 언어로 옮겨 쓴다.

**왜 넣는가.** 상태 점검은 하네스가 낡는 것을 훅 없이 알아채기 위한 것이다. 신호가 없으면 아무것도 출력하지 않아 비용이 거의 없다. 착수 전 확인은 요청을 넘겨짚고 한참 진행한 뒤 다시 하는 일을 줄이기 위한 것이다. 분명한 요청에는 묻지 않아야 오히려 시간을 아낀다.

---

```markdown
### 0-a. 상태 점검

프로젝트에 `harnesskit.lock`이 있으면 아래 경로 중 존재하는 것으로 실행한다.

- `python3 ~/.claude/skills/harnesskit/scripts/hklock.py status --brief --project .`
- `python3 ~/.codex/skills/harnesskit/scripts/hklock.py status --brief --project .`
- (Windows는 `python3` 대신 `python` 또는 `py -3`)

출력이 없으면 다음으로 넘어간다. 한 줄이 나오면 사용자에게 그대로 전하고, 지금 작업을 먼저 할지 점검(`harnesskit check` 또는 `harnesskit evolve`)을 먼저 할지 묻는다. HarnessKit이 없거나 스크립트가 실패하면 조용히 넘어간다.

### 0-b. 착수 전 확인

시작하기 전에 요청을 네 항목으로 나눠 본다.

| 항목 | 질문 |
|---|---|
| 목표 | 무엇을 끝내면 되는가 |
| 범위 | 무엇을 건드리고 무엇을 건드리지 않는가 |
| 입력 | 무엇을 근거로 하는가 (파일, 문서, 이전 결과) |
| 완료 기준 | 무엇을 보면 끝났다고 판단하는가 (테스트 통과, 표 완성, 검토 통과) |

- 네 항목이 요청과 프로젝트 맥락에서 모두 분명하면 묻지 않는다. 해석을 한 줄로 밝히고 시작한다.
- 불분명한 항목만 묻는다. 질문 수는 작업 크기에 맞춘다: 작은 작업 최대 1개, 일반 작업 2개, 여러 에이전트가 여러 단계를 도는 작업 3~4개.
- 가능한 답을 선택지로 제시하고 추천안을 첫 번째에 둔다. Claude Code는 `AskUserQuestion` 도구가 있으면 쓰고, 없거나 Codex면 번호 목록으로 묻는다.
- 사용자가 "알아서", "바로 해"라고 하면 묻지 않고, 세운 가정을 밝힌 뒤 진행한다.
- 확정한 해석·가정·완료 기준을 `_workspace/00_preflight.md`에 적는다. 마지막 단계에서 이 완료 기준으로 결과를 점검하고 보고서에 적는다.
```
